# 面板设计

## 两个入口，一份核心

- **DSH 设置里的「传达室」**（`plugin/client/index.js`）：状态灯 + 三个按钮。管的是「后台进程在不在」。
- **网页**（`panel/index.html`）：白名单、会话列表、手动发。管的是「怎么用」。

两个入口读同一份 `panel/config.json`，不各存一份。

## DSH 那一页：三个按钮

```
[启动后台进程]  [停止后台进程]  [打开网页设置]  [窗口体检]  [刷新]
```

**为什么「启动」必须放在这里**：面板服务没跑的时候，网页打不开，网页里的按钮也点不到。
点击 → `POST /dsh-qq-idle/start`（插件在 DSH 里注册的路由）→ 插件 spawn `panel/server.mjs`
（`detached` + `windowsHide`）→ 最多等 3 秒，端口通了才算成功。

**「打开网页设置」**：`window.open('http://127.0.0.1:8765')`，只在后台进程在跑时可点。

**不做开机自启**：它是保底方案——用户会用它，就说明 SnowLuma 那条路已经失效了。
开机自启会和那条路抢窗口，也让「谁在操作 QQ」变得不清楚。要手动就手动。

**「停止后台进程」**（11-21 加）：先请面板自己退（`POST /api/shutdown`，它回完话就 `process.exit`），
三秒后退不掉，再按自己记下的 pid 收一次。**不按端口猜进程**——那等于在黑盒子上乱开枪。
面板自己那个页面上也有一个「停止后台进程」，效果一样（它就是那个进程本身）。

**「窗口体检」**（11-21 加）：一次跑 `qq-repaint -DryRun` 和 `qq-popups`，把「主窗有多少元素/文本节点」「有没有置顶浮窗挡着」直接摆在页面上。
这两天「QQ 白了」「屏幕一块点不动」都是这两件事，每次翻命令行太慢。填了 QQ 号就只体检那个号。

## 网页：会话与白名单

- 每行三态：**关 / 只读 / 可回**。默认关。
- 总开关：读、写分开，默认都关。
- 群聊必须带触发词才回（群里 @ 不一定读得到，先不承诺）。
- 改名检测：白名单里的名字这次没找到 → 提示 + 「迁移到 / 删掉」两个按钮。
- 重名检测：两个会话同名 → 标 `⚠重名`，提示去 QQ 改备注。

## 消息往哪儿存（这个还没定下来，先记着）

要解决的：QQ 进来一条、我回一条，这段上下文落在哪个工作区的哪个对话？

三个方案：

1. **每个联系人一个 DSH 会话**：分得清，但联系人多就一堆会话，每次都要新建、压缩、计费，而且绑死在 DSH 的会话机制上。
2. **统一进一个「传达室」会话**：省事，但多人混一起容易串。
3. **原文落文件 + 会话里只放摘要**（倾向这个）：
   - 原文：`~/.dsh/qq-idle/messages/<昵称>/<日期>.jsonl`
   - 配置里给一个「存档目录」字段，用户可以指到某个 world 的工作区里，让那个人格插件自己读
   - 家会话里只放「谁、什么时候、说了什么」一行

**方案 3 的好处**：不绑任何人格插件——原文是文件，谁想读谁读；world 那种自己管记忆的可以把目录加进归档范围，别的人格插件不理会也不冲突。

## 原文落盘（默认关）

面板上多了一块「原文落盘」：开关、目录、「现在落一次」。

- 只处理设成**可回**的会话——只读的我本来就不该替它说话，存全文没意义。
- 一行一条 jsonl：`{at, 时间, 谁, 内容}`，按 `<昵称>/<日期>.jsonl` 分。
- 目录默认 `~/.dsh/qq-idle/messages`；**指到某个 world 的工作区等于把聊天记录交给它**，界面上写明了。
- **不自动跑**：读消息要 Invoke 点开会话，会把你正在看的聊天切走。这件事得你点头才做成轮询。

## 不要做的事

- 不在面板里显示消息正文之外的隐私（不发 QQ 号、不显示群成员）
- 不做「自动回复全部会话」——白名单是硬的
- 面板不常驻后台：DSH 打开才起，关了页面就停（少一个常驻进程）
