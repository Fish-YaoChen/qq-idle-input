# 消息存在哪（一页，挑一个就行）

要解决的问题：QQ 进来一条、我回一条，这段上下文落在**哪个工作区的哪个对话**里。
现在完全没有答案——插件能读能写了，但「读过的东西归谁」没定。

## 三个方案，摆在桌上

### A. 每个联系人一个 DSH 会话

读到一个会话，就开一个 DSH 会话，消息进那个会话的上下文。

- **好**：分得干干净净，谁说的、聊到哪儿了一目了然；DSH 自己的压缩、检索、记忆全能用上。
- **坏**：联系人多就是一排会话；每条消息都可能触发一次上下文加载和计费；绑死在 DSH 的会话机制上，换人格插件就废了。
- **什么时候合适**：只跟一两个人聊，而且长期聊。

### B. 统一进一个「传达室」会话

所有来源都进同一个会话，由我在里面分派。

- **好**：只有一个上下文，省；跨联系人的事能连着看。
- **坏**：几十个人一起说话会串；「这句话是跟谁说的」得靠我自己记；上下文很快被撑爆。
- **什么时候合适**：来源少、话短、只想让我「知道一下」。

### C. 原文落文件 + 会话里只放一行摘要（我倾向这个）

- 原文：`~/.dsh/qq-idle/messages/<昵称>/<日期>.jsonl`，一行一条，谁、什么时候、说了什么、我回了什么。
- 配置里给一个「存档目录」字段，默认上面那个；想接进某个 world 就改成那个 world 的工作区路径。
- 家会话里只放一行摘要：「22:41 小林说『明天的会改到三点』，没设成可回，没回。」

- **好**：**原文永远在文件里，不依赖任何插件的记忆机制**；谁想读谁读（world 可以把目录加进归档，别人格不理会也不冲突）；上下文不爆；也不影响计费。
- **坏**：要读原文得自己去找文件；家会话里只有摘要，细节不在脑子里。
- **什么时候合适**：来源可能很多、又不想为每条消息付一次上下文。

## 顺带说清的三件事（不管选哪个都要定）

1. **什么时候写文件**：读的时候顺手写，还是单独一个后台进程定时读？
   现在 `qq-read` 是「查一次给一次」，没有「哪条是新的」这个概念——要落文件，先得加一个游标（上次读到哪条）。
2. **谁触发**：我在 DSH 里靠什么知道有新消息——定时轮询（简单，但一直占着），还是桥推给我（要桥配合，但及时）。
3. **存档目录要不要能被改**：默认放 `~/.dsh/qq-idle/messages/`；如果哪天你把它指进某个 world 的工作区，那个 world 就能「顺便」读到我们的聊天记录。**这一步得你点头**，我不默认打开。

## 我的建议

**C，加一条限制：只对「设成可回」的会话落原文，其余只记一行摘要。**

理由：原文是隐私最重的东西，而「只读」的那些会话我本来就不该替它说话——存全文没意义，还不如少存点。
可回的那几个，是真正会来回聊的，落全文才值。

要是你觉得「全部原样留着、以后好翻」，那就 C 不带这条限制——但存档目录就得更严一点（不放进任何 world 的工作区）。

## 选了之后我要做什么

- 选 A：改插件的读逻辑，加「会话 → DSH 会话」映射表；先做游标。
- 选 B：只加游标 + 一行摘要，半天。
- 选 C：加游标、写文件、摘要进家会话；半天。另外把 `qq-read` 的 `-Since` 参数做出来。

游标这件事三个方案都要，所以我先做游标——不等你定也能开工。

**11-21 已做完**：
- `qq-read -Open X -Messages -Since`：只吐上次之后的新消息，游标在 `~/.dsh/qq-idle/cursor.json`。
  消息的身份用「谁+内容」的指纹，不用时间（QQ 的时间戳会变成「昨天 18:21」，过零点意思就变）。
- `qq-read -Sessions`：哪个会话有新动静，前面标 ●；状态在 `~/.dsh/qq-idle/sessions.json`。

所以现在只剩「存哪儿」这一个决定，剩下的活儿（落文件 / 建会话 / 摘要）都在这之上。
